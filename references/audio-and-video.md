# 配音对齐、合成与成片核对

用于用户提供配音后将已确认独立分镜整合成视频。按当前环境发现工具，以下命令中的路径和名称都应换成本期实际值。

## 1. 检查原声音

用 ffprobe 查看容器、音视频流和时长。用户可以提供音频或带口播的视频；不能因为上传的是视频就把它当作需要沿用的画面。文件扩展名也不能说明真实容器。

```text
ffprobe -v error -show_format -show_streams -of json SOURCE
ffmpeg -i SOURCE -map 0:a:0 -vn -c:a copy voice.m4a
```

第二条适合原音轨为 AAC 的情况；其他编码选择相容容器或必要的高质量转换。保存源文件，配音提取不截头、不截尾、不改变语速。没有音轨时向用户说明缺失，再继续独立可完成的素材整理。

若上传视频有字幕，可提取开头、中段、结尾画面辅助核对口播。不要自动把源视频画面叠在已确认分镜上。

## 2. 得到时间并匹配原稿

优先使用现有字幕或当前可用的本地逐词识别工具，例如 Vosk 中文模型；其他引擎可采用同等结果。识别引擎和模型由使用者准备，不能假定安装本 skill 后自动具备转写能力。

统一转成秒为单位的词记录：

```json
{
  "words": [
    {"word": "为什么", "start": 0.10, "end": 0.40},
    {"word": "有时", "start": 0.42, "end": 0.70}
  ]
}
```

原稿和识别文本按字符匹配：忽略标点及空白，把词的起止均分给字符，再用动态规划匹配两条字符序列。数字读法等映射应根据本期实际识别结果明确提供，不能沿用别期的“1914”“2020”等替换。

`scripts/align_narration.py` 自动完成连续口播的初步对齐：

```text
python scripts/align_narration.py --manifest EPISODE/manifest.json --words WORK/words.json --audio-duration ACTUAL_SECONDS --output WORK/timeline.json --srt DELIVERY/字幕.srt
```

默认 30 fps、提前约 0.06 秒切图、末尾约 2 秒静音留图；可用 `--fps`、`--lead`、`--tail` 调整。需要数字等规范化时加 `--normalization WORK/replacements.json`，内容示例为 `{"replacements": [["2024", "二零二四"]]}`，仅用于匹配。

脚本输出每句起止帧、匹配方式、原稿与识别上下文、整体误差和 `needs_review_ids`。它不修改图片或原文，也不能把插值或同音替换解释为已人工核对。

### 人工核对重点

- 对不确定、极短、漏读、重复、同音替换、首尾句查看音频或源字幕帧。
- 若相邻两句得到同一切换帧或某句过短，脚本拒绝给出可用时间表；检查漏读/分镜切分后修正，不能随意挤出假的时长。
- 大量误差可能说明配音与稿件不一致；核对版本，不把改稿的音频强行套到旧图。
- 源视频有字幕时，在切换后约 0.1 秒处查看，确认正在说本句；再听切换前后确认停顿。
- 识别错字只影响匹配核对，不能把 ASR 错字写进图片字幕。

时间表先按整数帧确定再转成秒，相邻画面无空隙或重叠。第一张从 0 秒开始，最后一张覆盖到配音结束及尾部停留。自然停顿通常继续显示当前画面。

### 无旁白页面

互动或其他没有口播的画面不能只靠字符匹配定位。按其在口播中的位置人工安排约 2 秒，必要时在对应音频位置加入等长静音，并同步平移后续声音与切换时间。保留所有原口播。不要在每句后自动追加静音。

## 3. 制作可编辑合成工程

使用 HyperFrames 时，开始视频阶段先读取当前可用 `hyperframes` 入口，再按其路由使用长篇自定义合成工作流以及 composition/CLI 说明。读取新工程的 AGENTS 指令。模块化静态图片合成可作为默认实现，不照抄旧 CLI 版本或机器路径。使用其他已获认可的合成工具时，保留同样的时间表、原声音和画面完整性要求。

- 新建独立工程；复制选中原图片到本期资源目录，核对复制前后哈希一致。
- 1920×1080 黑色画布，30 fps；每张图 `object-fit: contain` 完整显示。图片字幕是画面的一部分。
- 每个分镜独立子 composition，使用时间表的 `data-start`/`data-duration`，编号对应唯一 ID。
- 音轨放在根时间线，连续播放；不要由自定义定时器控制音频。
- 静态画面声明明确时长，保持直接切换。不要添加占位动画来满足工具检查或优化。
- 使用本地可用的运行时资源，避免成片在运行时依赖外部网络。
- 若采用媒体清单工具，确认原口播被标记为 voice/narration；自动识别为 BGM 时纠正分类，不能按背景音乐处理。
- 默认不加入第二字幕层、配乐、音效或镜头缩放。

预览和检查通过后导出实际 MP4。用户明确要求整合与导出后，制作预览是工作环节，不需要再次停下来请求相同授权。

## 4. 工具故障处理

- Node、npx、ffmpeg 不在 PATH 时先发现已有运行时和缓存；需要局部启动器时放在本期工作目录，使用每条命令的 PATH，不更改系统变量。
- HyperFrames 的 ffmpeg 路径可通过当前支持的环境变量设置；以当前 CLI 帮助为准。
- 检查器没有 DOM 文本时，文本对比度检查为空并不能说明图片里的字幕清晰。
- 工具错误记录简短原因与已完成阶段，不把大段 HTML、转写全文或二进制数据反复打印给用户。
- 出错时保留工程和已完成素材，先修复当前阶段；云端渲染、收费替代服务等不是默认故障回退。

## 5. 核对实际成片

检查导出结果，而非仅检查 HTML 或时间表：

1. ffprobe 确认时长、分辨率、帧率、视频帧数、H.264/AAC 等实际输出属性。
2. 提取每张分镜的中段帧、每次切换前后相邻帧，以及开头与结尾，核对画面顺序和是否出现空白。
3. 对照源图片按相同比例缩放后的画面；必要时用像素差辅助发现错序或黑帧，但最终看实际截图。
4. 查看成片总览和有疑点的原尺寸截图，确认字幕、头发和道具完整。
5. 解码原音和输出音为同采样率 PCM，检查时长、偏移及相关性，确认声音没有缺失、替换或意外移位。编码有差异时不要求音频文件哈希相同。
6. 检查末尾约 2 秒留图静音，确保末句完整播放。

检查记录填写本次实际采样数和结果，不能把示例数据预填为已经完成的检查。

## 6. 成片交付

交付完整 MP4，可附 SRT、逐句时间表和成片总览。SRT 便于以后编辑，不默认再次烧进已有字幕的图片。用绝对本地路径提供可播放预览及下载链接，简短说明实际时长和格式。

用户要求上传章节节点时，另按实际内容转折列出“分:秒 + 十字以内概述”；不把每一句分镜都当成章节。
